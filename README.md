# Agentic Development Governance Template

**IDE-agnostic governance** for multi-agent development and delivery. Works with **OpenCode**, **Cursor**, **Zed**, and **VS Code** — OpenCode ships the richest runtime wiring; other IDEs load the same `.agents/` role packs and `AGENTS.md`.

**Project page:** [jensonchew.github.io/projects/agentic-dev-governance](https://jensonchew.github.io/projects/agentic-dev-governance/) · **IDE setup:** [docs/IDE_ADAPTERS.md](docs/IDE_ADAPTERS.md)

## What this is

A **stack-agnostic** starter template for building software with AI coding agents using an orchestrator-led **development and delivery** workflow. Agents follow phased governance—context mapping, spec-before-implement, isolated implementation, and independent review—instead of improvising in a single thread.

## Who it's for

- Solo developers or teams using **Cursor, OpenCode, Zed, or VS Code** with multi-agent workflows
- Repos that want **role separation** (orchestrator vs implementer vs reviewer) without inventing governance from scratch
- Anyone who needs a portable harness they can fork and configure for their stack

## What this is NOT

- **Not a personal AI assistant** — no Telegram gateway, messaging, or runtime product code
- **Not runtime governance** — no session audit, circuit breakers, or production ingest gates (that is a separate concern in a deployed assistant)
- **Not OpenCode-only** — `opencode.json` is optional convenience; governance lives in portable markdown under `.agents/`
- **Not compliance-certified** — this is an engineering workflow template, not a certified security or PDPA product

## Quick start

### Any IDE

1. Click **Use this template** on GitHub (or clone this repo).
2. Read [`AGENTS.md`](AGENTS.md) and [`docs/IDE_ADAPTERS.md`](docs/IDE_ADAPTERS.md) for your editor.
3. Customize `REPOSITORY-CONTEXT.md` for your repo (or run `/setup` in OpenCode to generate it).
4. Use phased workflows from `.agents/roles/` — context → spec → implement → review.

### OpenCode (recommended for orchestration)

1. Open in OpenCode and run `/setup` with your stack, e.g. `Go backend with Chi, React frontend with Vite`.
2. Review generated `REPOSITORY-CONTEXT.md` and `.agents/instructions-stack.md`.
3. Use the **development orchestrator** for non-trivial work.

### Cursor / Zed / VS Code

Load `AGENTS.md`, point rules at `.agents/` charters, and follow role files manually or via harness skills. See [docs/IDE_ADAPTERS.md](docs/IDE_ADAPTERS.md).

## What this template provides

- Multi-agent governance in `AGENTS.md`
- **Development**: context mapping, design analysis, spec writing, implementation, review, security review, migration planning, UI design
- **Delivery**: pipeline review, platform evaluation, security, observability, cost challenge
- Shared agents: context mapper, docs updater
- Universal engineering rules in `.agents/instructions.md` (with topic sub-files)
- Stack-specific rules generated by `/setup` in `.agents/instructions-stack.md`
- Repository memory in `REPOSITORY-CONTEXT.md`
- Reusable skills in `.agents/skills/`
- Just-in-time context loading — agents load only what their current task requires

## Setup details

### Run `/setup`

The setup command walks you through configuring the agent system for your stack:

```
/setup Go backend with Chi, React frontend with Vite, PostgreSQL with sqlc
```

Or run `/setup` interactively. This generates:

- Completed `REPOSITORY-CONTEXT.md` with your paths, commands, and conventions
- `.agents/instructions-stack.md` with language and framework-specific rules
- Agent bash permission recommendations for your build tools

### Review and start

Check that `REPOSITORY-CONTEXT.md` and `instructions-stack.md` match your repository. The development orchestrator will gather context, write specs for non-trivial work, coordinate implementation and review, and hand off to delivery when runtime concerns begin.

## Context loading model

Agents use **just-in-time loading** — they do not pre-load all governance and instruction files.

| Layer | Loaded | When |
|-------|--------|------|
| `AGENTS.md` | Globally via opencode.json | Always |
| `REPOSITORY-CONTEXT.md` | By each agent | Every invocation |
| Charter (development or delivery) | By agents in that charter | When governance context needed |
| `instructions/<topic>.md` | By any agent | Only when that topic is relevant |
| Orchestrator sub-files | By orchestrators | Only when entering that phase |
| Governance sub-files | By any agent | Only when governance questions arise |

See `AGENTS.md` "Context loading" section for the full model.

## Working model

### Development
- **Orchestrator** coordinates all development work
- **Context Mapper** maps affected files, dependencies, and blast radius
- **Design Analyst** explores options (explore mode) and grounds recommendations (ground mode)
- **Architecture Challenger** stress-tests proposals for drift and hidden coupling
- **Migration Planner** sequences schema and contract changes safely
- **Spec Writer** creates execution contracts for implementers
- **Implementer** writes code and tests in isolated worktrees
- **Reviewer** independently validates implementation
- **Security Reviewer** reviews application-level security
- **UI Designer / UI Reviewer** shape and critique frontend work

### Delivery
- **Orchestrator** coordinates delivery evaluation
- **Pipeline Engineer** reviews CI/CD and release flow
- **Platform Evaluator** assesses runtime fit, topology, and cost proportionality
- **DevSecOps Reviewer** reviews delivery-path security
- **Observability Engineer** reviews operational readiness

### Shared
- **Context Mapper** serves both charters
- **Docs Updater** maintains documentation and repository memory

## Customization

- `AGENTS.md` — root governance (rarely needs changes)
- `.agents/development.md` / `delivery.md` — charter-level governance
- `.agents/roles/**/*.md` — agent role definitions (agent-agnostic)
- `opencode.json` — agent runtime config: models, temperatures, permissions (OpenCode-specific)
- `.agents/instructions.md` — engineering rules hub
- `.agents/instructions-stack.md` — stack-specific rules (generated by `/setup`)
- `REPOSITORY-CONTEXT.md` — repository facts, commands, conventions
- `.agents/skills/` — reusable agent-agnostic skills
- `.opencode/skills/` — OpenCode-specific skills

## Notes

- `REPOSITORY-CONTEXT.md` is repository-specific and should evolve over time
- `.agents/instructions.md` contains universal rules — modify only for template-wide changes
- `.agents/instructions-stack.md` is generated — re-run `/setup` when your stack changes
- Run `/setup` again any time your tech stack, build tools, or architecture changes materially
- Agent-agnostic content lives in `.agents/`; only OpenCode runtime config lives in `.opencode/`
