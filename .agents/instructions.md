# Repository Engineering Instructions

Universal engineering law for agents working in this repository.
Stack-specific rules live in `REPOSITORY-CONTEXT.md` and optionally
in `.agents/instructions-stack.md`.

---

## Context

- `AGENTS.md` defines governance and charter structure
- `REPOSITORY-CONTEXT.md` defines current repository facts and stack rules
- `.agents/instructions-stack.md` defines stack-specific engineering rules (generated by `/setup`)
- this file defines how work must be done in any repository using this agent system

## Scope

These instructions apply to:
- context mapping
- spec writing
- implementation
- review
- documentation updates where engineering rules matter

If guidance conflicts, follow the precedence defined in `AGENTS.md`.

---

## Detailed rules

Load only the rule file relevant to your current task — not all of them:

| When your task involves... | Load |
|----------------------------|------|
| Layer boundaries, cross-stack contracts | [architecture.md](instructions/architecture.md) |
| Scope control, language rules, packages | [implementation.md](instructions/implementation.md) |
| Test coverage, testing tools | [testing.md](instructions/testing.md) |
| Build commands, validation reporting | [build.md](instructions/build.md) |
| Persistence, schema, data access | [data.md](instructions/data.md) |
| Review criteria, blocking vs suggestions | [review.md](instructions/review.md) |
| Documentation updates | [documentation.md](instructions/documentation.md) |
| Pre-existing warnings or failures | [known-issues.md](instructions/known-issues.md) |

---

## Repository structure

Agents must:
- preserve the existing repository structure once the repo is customized
- prefer extending established module, feature, and project boundaries
- avoid introducing parallel structures for the same concern
- escalate when the repository shape is unclear or incomplete

Repository-specific paths, commands, and architecture facts belong in
`REPOSITORY-CONTEXT.md`.

---

## Escalation

See [`.agents/governance/escalation.md`](governance/escalation.md) for the
full escalation trigger list. The "Engineering instructions additions" section
defines triggers specific to implementation work.

---

## Project setup

When this template is used for a new repository, run `/setup` to configure
the agent system for your specific tech stack. The setup command generates:
- `REPOSITORY-CONTEXT.md` with correct paths, commands, and conventions
- `.agents/instructions-stack.md` with language and framework-specific rules
- Agent bash permission updates for your build tools

Run `/setup` again when the stack changes materially.

---

## Final principle

Follow repository reality and existing patterns. When in doubt: stay within
approved scope, preserve layer boundaries, reuse existing patterns, test
changed behavior, update repository memory when facts change, escalate before
making broad architectural moves.
